# ZZZ 风格动作 Demo

基于 Unity 的第三人称动作战斗原型。包含一套完整的战斗闭环：玩家移动 / 连击 / 特殊技 / 终结技演出，敌人索敌与战斗 AI，失衡破防与 QTE 连携，队伍切换，以及大厅侧的登录、抽卡图鉴与频道聊天。

## 运行环境

| 项目 | 说明 |
| --- | --- |
| Unity | 6000.3.x（Unity 6） |
| 渲染 | URP |
| 输入 | Input System（`.inputactions` 资产） |
| 相机 | Cinemachine |
| 动画 | Animator + 根运动 + 动画事件 |
| 配置 | ScriptableObject |
| UI 动画 | DOTween（Git 依赖包） |

## 快速开始

1. 用 Unity 6000.3.x 打开工程根目录，等待包还原与脚本编译。
2. 打开 `Assets/Scenes/SampleScene.unity`，点击 Play 即可体验战斗。
3. 大厅（Lobby）与登录（Boot）场景分别演示抽卡图鉴、怪物选择与本地聊天。

测试账号：`test / 123456`（LoginServer 本地校验）。

## 核心玩法系统

### 动作与战斗

- 状态机驱动：移动 / 待机 / 闪避 / 连击 / 技能 / 受击均由独立状态类实现，在状态基类中统一处理优先级与打断规则。
- 攻击吸附：每段攻击起手向范围内最近敌人转向并小幅推进。
- 命中窗口：动画播放到配置区间时结算伤害，命中附带顿帧与相机震屏。
- 终结技演出：隔离场景、切换深蓝雾效天空、闪现到目标身边，在动画关键帧统一结算一次伤害。
- 敌人 AI：探测 → 追击 → 攻击 → 受击 / 破防 / 死亡；受击累积失衡值，打满后进入眩晕并开启 QTE 窗口。
- QTE 连携：时停选人（慢动作 + 倒计时）→ 候补成员入场打出连携技 → 相机平滑交接。

### 表现细节

- 世界头顶血条：跟随敌人、距离缩放、屏幕外隐藏、掉血幽灵条与失衡条。
- 伤害飘字：对象池复用，普攻白字 / 暴击金字 / 受伤红字。
- 打击感：命中顿帧只冻结场上动画，不改 `timeScale`，震屏与 UI 不受影响。

### 大厅

- 抽卡：按 SSR / SR 权重抽取角色，结果展示立绘与角色介绍。
- 图鉴：12 名角色的收集进度与顶栏计数联动，存档使用 `PlayerPrefs`。
- 战斗选择：三档怪物难度，进入战斗后覆盖敌人数值并染色。
- 聊天与登录：TCP 本地模拟服务器，4 字节长度前缀分帧，网络事件统一回主线程。

## 代码结构

```
Assets/Script/
├── Entity/            # 实体 / 状态机 / 属性框架
├── Player/            # 玩家实体、输入、相机、动画与战斗状态
├── Enemy/             # 敌人实体、索敌、战斗请求与状态
├── BattleSystems/     # 切人、QTE、打击感、血条、飘字与结算
├── Lobby/             # 大厅：抽卡 / 图鉴 / 战斗选择 / 聊天
├── TCP/               # TCP 分帧、登录与聊天服务器客户端
├── Level/ UI/ Misc/   # 流程控制、UI 动画、日志与单例
└── Tools/             # 编辑器扩展（状态绘制、场景生成菜单）
```

设计要点：

- `Entity<T>` 把控制器、状态机与属性组合在一起；状态列表以类名配置在 Inspector 中，运行时反射创建。
- 玩家 / 敌人的伤害、索敌、吸附、命中、镜头演出等逻辑拆成单一职责类，实体只保留公开接口。
- 敌人与玩家注册表替代频繁的全场景查找，命中检测与索敌直接遍历注册表。
- 战斗属性集中在 ScriptableObject 资产中，数值调整不改代码。

## 扩展指南

### 新增玩家状态

1. 在 `Player/States/` 新建继承 `PlayerState` 的状态类，实现生命周期方法。
2. 在场景中 `PlayerStateManager.states` 数组追加类名。
3. 需要动画时，在 Animator 中加入同名状态。

### 新增敌人状态

同上，继承 `EnemyState` 并在 `EnemyStateManager.states` 登记；敌人状态的进入优先级在基类 `Step` 中统一检查。

### 调整抽卡角色

- 角色定义在 `Lobby/CharacterData.cs` 的角色目录中。
- 立绘放在任意 `Resources/抽卡素材/` 目录，名称顺序与 `GachaArt.k_OrderedFileNames` 对应。

### 新增动画 / 技能

- 动画名必须与 Animator 状态名完全一致。
- 终结技如需特写镜头，在动画中添加事件，函数名固定为 `Player.OnFinishSkillCameraEvent`。

## 注意事项

- Animator 必须开启 Apply Root Motion，且不要禁用所在脚本的 `OnAnimatorMove`。
- 代码通过 `.meta` GUID 被场景引用，修改类型名会导致场景丢失组件，改动类名时需同步处理场景引用。
- 敌人与玩家状态类名与 `states` 数组配置一一对应，漏配会打印错误并跳过该状态。
